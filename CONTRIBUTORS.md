## Review of Future Changes

Create a branch and a pull request describing the concrete change and its relevant validation. Review firmware settings, CSI decoding, feature order and class labels together where a change affects model compatibility. Preserve the fixed baseline; new experiments must use distinct outputs and disclose their splits. A team member or owner should review changes before merge. This is the intended review workflow, not a claim that branch-protection rules were enabled.

Each student should submit genuine changes through their own authenticated GitHub account. Do not manufacture commits, add fictitious authors or rewrite authorship. GitHub's automatic Contributors page is based on actual qualifying commit attribution. Invitation status must be checked in repository settings; a pending invitation is not active access. The private repository requests ordinary Write collaboration, not Administrator permission.
